# image-factory

A reusable GitHub Actions pipeline that builds container images which can be
checked by a stranger.

One base image (Debian slim) and one language runtime built on its digest.
Pinned, scanned, catalogued, signed, attested, and then verified by pulling the
result back out of the registry. Free tooling, GitHub-hosted runners, one
maintainer.

```sh
./verify.sh --image ghcr.io/OWNER/base@sha256:… --repo OWNER/image-factory
```

That command needs `cosign`, `syft` and `jq`, and nothing else. No account, no
credentials, no trust in this repository. It is the same script the pipeline
runs against its own output, so a green build means this exact code path passed.

---

## What is guaranteed

Each of these is enforced by a job that fails the build, and by a check in
`verify.sh` that runs against the published artefact.

| Guarantee | How it is enforced |
|---|---|
| Every image reference used to build is immutable | `scripts/assert-pinned-digests.sh` rejects any `FROM`, `COPY --from=`, `RUN --mount=from=` or `# syntax=` that is not `@sha256:<64 hex>`, including ones hidden behind an `ARG` |
| A build-arg cannot smuggle in a tag | `*_IMAGE` / `*_BASE` build-args are checked for a digest before the build starts |
| No fixable HIGH or CRITICAL vulnerability at build time | Trivy scans the **pushed** image pulled from the registry; fixable HIGH/CRITICAL fails the build |
| Unfixable findings are visible, not swallowed | recorded in `unfixable.json` and printed in the job summary |
| An accepted finding has a reason and an end date | exceptions carry `reason` and `expires`; an expired entry fails the build with exit 73 |
| The SBOM describes the published artefact | Syft runs against `registry:<image>@<digest>`, never the build context |
| The SBOM is not empty | package count must exceed the configured floor, and SPDX and CycloneDX must agree |
| The image and its SBOMs are signed | Cosign keyless via GitHub OIDC; SBOMs as signed in-toto attestations |
| Provenance comes from a builder this workflow cannot forge | `slsa-framework/slsa-github-generator`, a separate isolated builder |
| The signature is bound to a specific identity | `verify.sh` refuses to run without an expected signer, and fails a permissive regexp such as `.*` |
| Every attestation is about *this* digest | subject digests are compared against the digest under test |
| Verification actually ran | `verify.sh` writes a receipt; the pipeline asserts `ran == required`, `failed == 0`, `skipped == 0`; a final `gate` job with `if: always()` fails when any stage is skipped, cancelled or never scheduled |
| The gates can fail | `tests/` proves each gate rejects bad input with a specific exit code, not merely a non-zero one |

## What is not guaranteed

Stated plainly, because a supply-chain claim that hides its edges is worse than
no claim.

- **Not reproducible.** Two builds of the same commit produce different
  digests. `apt-get upgrade` pulls whatever the Debian mirrors serve that
  minute, and timestamps differ. Provenance tells you how an image was built;
  it does not let you rebuild it bit for bit.
- **A clean scan is a statement about one moment.** It means no fixable
  HIGH/CRITICAL was known to Trivy's database when the image was built. Images
  rot. The weekly rebuild exists for this reason, and it is not a substitute
  for you scanning what you actually run.
- **The SBOM is as complete as Syft.** Anything Syft has no cataloguer for —
  vendored source, a binary copied in by hand, something installed by a script
  — will not appear. An absent package is not evidence of absence.
- **SLSA level is not claimed as a number here.** Provenance is generated by
  the SLSA GitHub generator on a GitHub-hosted runner. Read its own
  documentation for what level that gives you under your threat model. This
  README will not launder that into a badge.
- **Upstream trust is unchanged.** Pinning a digest makes the base immutable.
  It does not make it trustworthy. If the Debian image you pinned was already
  compromised, this pipeline will faithfully sign and attest the compromise.
- **Signing proves origin, not quality.** A valid signature means this
  workflow in this repository produced this digest. It says nothing about
  whether the image is fit for your purpose.
- **Rekor is public.** Keyless signing writes your repository name, workflow
  path and image reference to a public transparency log, permanently. Do not
  use this for images whose existence is confidential.
- **`linux/amd64` only.** Multi-architecture builds turn the manifest into an
  index and change what the signature covers. Out of scope for v1 rather than
  half-done.
- **Runtime security is out of scope.** No admission control, no policy
  enforcement in your cluster, no seccomp or AppArmor profiles.
- **Third-party actions are pinned to floating major tags**, not commit SHAs,
  so that this repository actually runs when you clone it. Dependabot watches
  them. If your threat model requires SHA pinning, do it before first use — it
  is a real gap and it is listed here rather than in a footnote.

## Setting it up

You need a GitHub account. Nothing else, and nothing paid.

```sh
git clone <your fork>
cd image-factory
```

1. **One line to change.** In `.github/workflows/build-image.yml`, set
   `env.FACTORY_REPO` to your fork, e.g. `you/image-factory`. The pipeline
   refuses to run while it is the placeholder.
2. **Pin the bases.** The Dockerfiles ship with obviously-fake all-zero
   digests. Resolve them:
   ```sh
   make pin
   git diff            # read it
   git commit -am "pin base digests"
   ```
   Also replace `REPLACE_ME` in the `LABEL` and `ARG BASE_IMAGE` lines.
3. **Confirm the SLSA generator tag.** `build-image.yml` calls
   `slsa-framework/slsa-github-generator/.github/workflows/generator_container_slsa3.yml@v2.1.0`.
   That reference must be a tag, not a SHA, because verification matches on it.
   Check the tag exists and is current before the first run.
4. **Run the self-tests locally.** No network, no registry:
   ```sh
   make test
   ```
5. Push to `main`. `release.yml` builds `base`, then builds `python` on the
   digest that base build produced.
6. Make the packages public in your GitHub package settings if you want anyone
   to be able to verify them.

## Layout

```
.github/workflows/build-image.yml   the reusable pipeline (workflow_call)
.github/workflows/release.yml       builds base, then runtime on its digest
.github/workflows/ci.yml            shellcheck and the self-tests
.github/image-factory/exceptions.json
images/base/Dockerfile              Debian slim, patched, non-root, no setuid
images/python/Dockerfile            python3 on the factory base
scripts/assert-pinned-digests.sh    the pinning gate
scripts/scan.sh                     Trivy plus the exception policy
scripts/sbom.sh                     Syft, SPDX and CycloneDX
scripts/pin.sh                      resolve a tag to a digest, in place
scripts/lib.sh                      the exit-code contract
verify.sh                           external verification, also used by CI
tests/                              proof that the gates reject bad input
examples/consumer-repo/             a repository consuming the pipeline
```

## Exit codes

Scripts never exit 0 for an audit that did not finish. `0` means the audit ran
and the subject passed; anything else names the reason.

| Code | Meaning |
|---|---|
| 0 | audit completed, subject passed |
| 1 | audit completed, subject failed policy |
| 64 | bad arguments |
| 70 | a required tool was missing |
| 71 | nothing to audit — the check would have been vacuous |
| 72 | a needed value could not be resolved |
| 73 | an exception outlived its expiry |
| 74 | artefact verification failed |
| 75 | the audit aborted before completing |

71 exists because "no violations found in zero files" is the most common way a
supply-chain check lies to you. Every list in this repository is asserted
non-empty before anything is concluded from it.

## Exceptions

When a fixable HIGH or CRITICAL has no viable fix today, the answer is not to
lower the threshold. Add an entry to
`.github/image-factory/exceptions.json`:

```json
{
  "exceptions": [
    {
      "id": "CVE-2026-12345",
      "package": "libssl3",
      "reason": "fix is in trixie only; backport not yet in bookworm-security",
      "expires": "2026-12-01",
      "owner": "hossein"
    }
  ]
}
```

The build fails on the day it expires. That is the mechanism working, not a
mechanism to route around. `package` may be `"*"` to accept the id wherever it
appears.

## Verifying something built elsewhere

```sh
./verify.sh \
  --image ghcr.io/someone/thing@sha256:… \
  --repo someone/thing \
  --strict
```

`--repo` derives the expected signer identity. If you pass
`--identity-regexp '.*'` instead, verification fails: a signature check that
accepts any signer proves only that the image was signed by somebody, which is
not a property worth having.

Add `--receipt out.json` for a machine-readable ledger of every check.
